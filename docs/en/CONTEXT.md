# repowiki

[中文](../zh/CONTEXT.md) | **English**

A deterministic build system that generates a structured wiki for any code repository:
the CLI handles orchestration and validation; the intelligent work (reading code,
writing) is done by the agent driving it.

## Language

### Artifacts

**Repo Wiki**:
The complete structured document set generated for a target repository, placed in its
`.repowiki/` directory.
_Avoid_: documentation site (that's the Wiki Site), docs

**Wiki Page**:
The basic writing unit of the wiki: one markdown file with a fixed template structure
(citation block, TOC, required sections, mermaid diagrams).
_Avoid_: article, entry

**Section**:
A top-level thematic grouping that organizes wiki pages; one section may contain
multiple pages.
_Avoid_: directory (confusable with Catalog), module

**Overview**:
The reader-facing front page of the whole wiki: repo intro, section navigation, and
usage advice; the final task before finalize.
_Avoid_: README, home page

**Source Reference**:
A `file://` link in a page pointing at a repository source file (optionally with a line
range), guaranteeing every conclusion traces back to code.
_Avoid_: citation, anchor (anchor refers only to on-page TOC jumps)

**Metadata Index**:
The machine-readable index produced by finalize: section tree, source files, code
snippets, and their relations to pages.
_Avoid_: manifest, database

**Knowledge Card**:
Optionally generated mechanism cards (config, logging, error handling, etc.) and module
docs, separate from the page system.
_Avoid_: notes, ADR card

**Wiki Site**:
The **single-file offline HTML** viewing artifact generated by the `site` command after
finalize: embeds all pages, the rendering libraries, and the referenced source lines;
open it in a browser with a double-click.
_Avoid_: preview, web version (no server involved), static site directory

### Orchestration

**Catalog Planning**:
The first task of the whole flow: after reading the repository, the agent produces the
section tree and each page's outline — the basis for all subsequent page tasks.
_Avoid_: table of contents page, TOC

**Task**:
The smallest unit of work handed out by the orchestrator, with a unique id, type,
output path, and spec; states are only pending / in_progress / done / failed /
exhausted.
_Avoid_: job, ticket

**Task Spec**:
The complete writing instructions embedded in each task (template, style guide, hint
file list), so any worker can execute it with no extra context.
_Avoid_: prompt

**Phase**:
The sequential gate between task kinds: catalog → pages → overview; later-phase tasks
are not handed out until the earlier phase completes.
_Avoid_: step, phase gate

### Execution

**Worker**:
Any executor running the task loop (subagent / process / human); it obtains tasks by
claiming and holds them via heartbeats.
_Avoid_: agent (confusable with the agent driving the CLI), process

**Claim**:
A worker's atomic exclusive hold on a task; at most one valid claim per task at any
moment.
_Avoid_: lock, checkout

**Expired Claim**:
A claim not renewed within the heartbeat window; it is automatically reclaimed and
re-queued — this is the queue self-healing.
_Avoid_: deadlock, zombie task

**Heartbeat**:
A worker's periodic renewal of its claim during execution; the only liveness signal.
_Avoid_: ping, health check
