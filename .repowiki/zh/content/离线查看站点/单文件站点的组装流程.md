## 简介
「单文件站点的组装流程」聚焦 `repowiki site` 如何把全部 wiki 页面、源码片段与前端运行时打成一个完全离线、可双击打开的 HTML 文件。`site.py` 的 `run_site` 是入口：校验 `repowiki-metadata.json` 存在、按 catalog 顺序收集页面正文、用 `extract_refs` 抽出所有 `file://` 引用的源码行区间、用 `templates/site.html` 拼装 shell、把 marked 与 mermaid 的 vendored JS 内联进 `<script>` 块，最终把结果原子写入 `<repo>/.repowiki/<locale>/wiki.html`。本节解释这一组装流水线，包括页面顺序的回退、源码片段的二进制防护、主题切换与 mermaid 主题变量等关键设计。

## 项目结构
围绕 `site` 命令这条主线，仓库内相关的产物集中在以下几个位置（路径相对仓库根）：

- `src/repowiki/site.py`：253 行的站点组装模块；包含 `run_site / _collect_pages / _ordered_nodes / _nodes_from_disk / _build_nav / _collect_snippets / _render_html / _vendor / _script_safe` 等函数。
- `src/repowiki/templates/site.html`：单文件站点的 HTML 骨架；design tokens CSS 变量 + 暗/亮主题（`color-scheme` 跟随系统）+ `prefers-reduced-motion` 适配；body 含 topbar（菜单/面包屑/主题按钮/阅读进度条）、可折叠侧边栏（导航树 + 页内目录）、内容区 + pager、页脚与源码弹层；外加四个 `PLACEHOLDER`（内容为 `SITE_PAYLOAD` / `MARKED_JS` / `MERMAID_JS` / `APP_JS`）被 `templates.render` 替换。
- `src/repowiki/templates/site/app.js`：前端应用逻辑（marked 渲染、mermaid 初始化、主题切换、源码弹层、搜索）；同样在 `_render_html` 中读取并 `_script_safe` 转义。
- `src/repowiki/vendor/marked.min.js` 与 `src/repowiki/vendor/mermaid.min.js`：内嵌的渲染库（MIT），通过 `package-data` 声明随 wheel 打包，保证离线可看。
- `pyproject.toml:31-32`：`package-data` 声明把 `templates/site.html`、`templates/site/*`、`vendor/*.js` 一并打入 wheel。
- `<repo>/.repowiki/<locale>/wiki.html`：最终产物；带侧边栏导航、全文搜索、源码弹层、主题切换。

## 核心组件
- `run_site`（`site.py:28-72`）：入口；先校验 `metadata_file` 存在并可解析，按 catalog 顺序收集页面，构造 nav 与源码片段，组装 payload，调 `_render_html`，原子写入 `<locale>/wiki.html`；`--open` 时用 `webbrowser.open(out.as_uri())` 在浏览器打开。
- `_collect_pages`（`site.py:89-114`）：从 metadata 与 overview 文件开始，按 `nodes` 顺序读取每个 `.md`，把 markdown 文本塞进 `pages` 列表。
- `_ordered_nodes / _nodes_from_disk`（`site.py:117-156`）：先尝试用 `state/catalog.json` 的 plan 顺序；若 catalog 缺失或解析失败，回退到「按磁盘目录序」的章节/页面推断——保证 `repowiki clean` 之后站点仍可重建。
- `_build_nav`（`site.py:159-190`）：基于 nodes 的 parent-child 关系构造侧边栏树，overview 置顶，章节下的页面递归纳入。
- `_collect_snippets`（`site.py:195-215`）：用 `validate.extract_refs` 抽出每页的 `file://` 引用，按行区间读源码并内联；二进制或过大区间标 `missing` 跳过。
- `_render_html`（`site.py:232-242`）：把 payload 转 JSON、转义 `<` 防 XSS，读取 shell 与 app.js、用 vendor JS 填充模板四个占位符。
- `_script_safe`（`site.py:250-253`）：把所有内嵌 JS 里的 `</script` 替换为 `<\/script`——防止注入的脚本提前关闭 `<script>` 标签。

## 架构总览
从 `finalize` 完成后到「用户双击 wiki.html」的视角看，时序是：`run_site` 校验 `metadata_file` 与 `content_dir`；`_ordered_nodes` 优先读 `catalog.json`，缺失则用 `_nodes_from_disk` 按目录序回退；`_collect_pages` 收集 overview（来自 metadata 或 `overview.md`）与每页 markdown；`_build_nav` 构造侧边栏树；`_collect_snippets` 把所有 `file://` 引用对应的源码行内联成 snippets；payload 通过 `_render_html` 注入 shell 的四个占位符；最终用 `os.replace` 原子写入 `wiki.html`。前端 JS 启动后读 `window.SITE_DATA`，用 marked 渲染正文、mermaid 渲染图表，并按系统主题与用户点击切换深浅色；本次更新后渲染管线还依次执行代码块卡片化（复制按钮）、页内目录构建、pager 与面包屑填充、阅读进度条绑定。下图给出这一时序。

## 详细组件分析

### 入口与原子写入：`run_site`
- 职责：把 `payload` 渲染成 HTML 并原子写入 `<repo>/.repowiki/<locale>/wiki.html`；可选打开浏览器。
- 关键行为：先 `paths.metadata_file.is_file()` 校验 metadata 存在，缺失时抛 `UsageError("请先完成全部任务并运行 `repowiki finalize <repo>`")`（`site.py:29-32`）；构造 payload（repo/locale/generatedAt/ui/nav/pages/snippets）；调 `_render_html` 拿到 html；写入时用 `tmp = out.with_name(f".{out.name}.{os.getpid()}.tmp")` + `os.replace` 保证原子性（`site.py:56-60`）；`--open` 时 `webbrowser.open(out.as_uri())` 用 file:// URI 直接打开本地文件。
- 实现要点：tmp 文件名带 PID 避免并发 site 调用冲突；最终输出大小约 4-5 MB（README.md 提到），构造过程把全部 marked/mermaid JS 一次性内联。

### 页面收集与顺序回退
- 职责：按 plan 顺序或磁盘目录序收集页面 markdown 内容。
- 关键行为：`_ordered_nodes` 先尝试 `catalog.json` 的 `flatten(catalog, locale)` 结果；若 catalog 不存在或 JSON 损坏，回退到 `_nodes_from_disk`：扫描 `content_dir`，把每个含 `.md` 的子目录视为章节（`__chapter__.md` 作为占位输出），目录下每个 `.md` 视为页面；顶层 `.md` 视为独立顶级页（`site.py:130-156`）。

### 源码片段抽取与二进制防护
- 职责：把 wiki 页面里所有 `file://` 引用对应的源码行读进 snippets，供前端弹层使用。
- 关键行为：`extract_refs` 抽出 `(path, start, end)` 三元组；若 `start is None` 则按全文读；用 `_read_lines` 读文件并二分首 8192 字节含 `\0` 时判定为二进制（避免把图片/PDF 内联成巨长乱码），返回 `{"missing": True}`；区间超过 `MAX_SNIPPET_LINES = 20_000` 也标 missing 跳过，防止单文件膨胀（`site.py:25, 211-213`）。
- 实现要点：`max(s, e) / min(e or len(lines), len(lines))` 对行区间钳制，避免越界；同 key 已存在则 `continue` 去重。

### HTML 渲染与安全转义
- 职责：把 payload + 内嵌 JS 注入 shell 模板，输出最终 HTML。
- 关键行为：`payload_js = json.dumps(payload, ensure_ascii=False).replace("<", "\\u003c")`——把 JSON 字符串里出现的字面 `<` 转义为 `\u003c`，防止 `</script>` 提前关闭 `<script>` 块；`_vendor(name)` 读 `vendor/<name>` 并跑 `_script_safe`；`templates.render(shell, SITE_PAYLOAD=..., MARKED_JS=..., MERMAID_JS=..., APP_JS=...)` 一次性填四个占位符（`site.py:232-242`）。
- 实现要点：`_script_safe` 全局把 `</script` 替换为 `<\/script`，对 mermaid/marked/app.js 都生效——这是最稳的 JS 内联安全做法。

## 性能与一致性考量
- 站点大小：单文件约 4-5 MB；主要由 marked（~50 KB）+ mermaid（~500 KB）+ 全部 markdown + 全部源码片段构成；打开方式为本地 file://，无网络请求。
- 源码片段大小保护：`MAX_SNIPPET_LINES = 20_000`（`site.py:25`）——超过此区间的引用直接标 `missing` 跳过，避免一份 wiki 把整个 monorepo 内联进 HTML。
- 二进制文件防护：`_read_lines` 检查文件前 8192 字节是否含 `\0`，命中即视为二进制并标 missing——避免把图片/PDF 内联成超长乱码。
- 顺序一致性：`_ordered_nodes` 优先用 `catalog.json` 的 plan 顺序，保证 wiki 页面顺序与 `plan` 阶段一致；`repowiki clean` 后 catalog 缺失则用目录序回退，此时内容不受影响。
- 写入原子性：tmp 文件带 PID 后缀避免并发 `site` 调用冲突；最终 `os.replace` 在同一文件系统下保证读者要么看到旧版要么看到新版，不会读到半截。
- 主题切换性能：CSS 变量切换不重排版；mermaid 主题切换通常需要重新渲染图表，由前端 JS 异步完成。
- 模板占位符：四个大写键（`SITE_PAYLOAD` / `MARKED_JS` / `MERMAID_JS` / `APP_JS`）一次性替换进 shell；任一失败会让整页降级，但 site 命令本身不会因此失败——失败的 HTML 仍可写入但缺少对应能力。

## 故障排查指南
- 退出码 `1`（`UsageError: 未找到 repowiki-metadata.json`）：未运行 `finalize` 就跑 `site`；先完成全部页面任务并跑 `finalize`。
- 退出码 `1`（`repowiki-metadata.json 损坏`）：metadata JSON 解析失败；先重跑 `finalize`，确认所有 page task 状态为 `done`。
- 退出码 `1`（`未找到任何已生成的 wiki 页面`）：`.repowiki/<locale>/content/` 为空；通常发生在 `clean` 之后忘记重新 `plan + check`；重跑 `plan` 与各 page task 的 `check` 即可。
- 站点打开后源码弹层显示 `missing`：源码片段抽取失败；常见原因——(a) `MAX_SNIPPET_LINES = 20_000` 超限，(b) 文件被识别为二进制（前 8192 字节含 `\0`），(c) 文件路径错误；定位方式——`grep -n "missing" wiki.html` 或前端 console。
- 主题切换后 mermaid 图未刷新：mermaid 主题通常需要 `mermaid.run()` 重新渲染；前端 `app.js` 应负责该流程，若未生效检查 `app.js` 是否被正确替换（搜索 `mermaid.initialize`）。
- JS 报错：被内嵌 JS 里有 `</script` 字面量（例如有人在 markdown 里写代码块含 `</script`）；`_script_safe` 会处理大部分情况，但若直接 inline 用户内容到 JS 字符串仍可能有问题；前端 console 看具体报错栈。
- 站点体积过大：snippet 区间太大或 vendor JS 未压缩；检查 `MAX_SNIPPET_LINES` 与 markdown 引用是否合理。
- 离线 wheel 缺 vendor：检查 `pyproject.toml:32` 的 `package-data` 是否包含 `vendor/*.js`；`pip show -f repowiki | grep vendor` 应能看到 `vendor/marked.min.js`。

## 结论
`repowiki site` 是一个纯组装的渲染器——它把 metadata、catalog 顺序、page markdown、源码片段、内嵌 marked/mermaid 与 shell 模板拼成一个 HTML 文件。关键设计是「单文件离线可用」：所有运行时都打包进文件本身；源码片段有大小与二进制防护；nav 顺序在 catalog 缺失时优雅降级到目录序；主题切换通过 CSS 变量与前端 JS 协同实现。对于想要扩展站点能力的开发者，最自然的接入点是修改 `templates/site.html` 与 `templates/site/app.js`（前端样式与交互）；若需要新增「被内嵌的资产」，修改 `package-data` 与 `_vendor` 即可。**已更新**：shell 重构为 design tokens 双主题并新增进度条/页内目录/pager/页脚等骨架元素，四个占位注入点与组装流程保持不变。
