- 单一入口 `cli.py:main` 做 argparse 子命令解析与异常→退出码映射（ConflictError=2、StateError/UsageError=1），命令实现分属 `plan.py`/`dispatch.py`/`metadata.py`/`site.py`/`updater.py`/`knowledge.py`。
- 全部状态集中在目标仓库 `.repowiki/state/index.json`，`state.py` 用 flock（Windows `msvcrt`）串行化读改写，任务记录含 status/attempts/claim 心跳字段。
- 阶段门控 catalog → pages → overview：`check` 既是校验器也是扩张点（catalog/knowledge-plan 通过后自动展开后续任务），`next` 保持纯 FIFO 拉取、按 ID 操作只走 `check --task`/`release --task`。
- 任务规格（`state/tasks/<id>.md`）由 `tasks.py` 生成并内嵌完整模板与 STYLE，规格自包含使任意 worker 并行安全。
- 产出三层：`<locale>/content/` 页面、`knowledge/<locale>/` 知识卡片（finalize 聚合 `_index.yaml`/`_module.yaml`）、`<locale>/wiki.html` 单文件离线站点（vendor 内嵌 marked/mermaid）。
- 增量路径 `updater.py` 依赖 `catalog.json` 的 `dependent_files` 做 git diff → 受影响页面映射，并对知识卡片/模块联动刷新。
